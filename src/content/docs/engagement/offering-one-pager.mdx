## Three packaged offerings

| # | Offering | Duration | Best fit |
|---|---|---|---|
| 1 | **AVS Foundation + first migration wave** | 8–12 weeks | Datacenter exit, vSphere refresh, M&amp;A consolidation |
| 2 | **DR-to-AVS** with SRM or HCX DR | 6–10 weeks | Customers keeping primary on-prem, modernising DR |
| 3 | **Stretched cluster build** (active/passive metro) | 4–8 weeks | Mission-critical workloads needing near-zero RPO |

> Long-tail migration waves typically run 6–18 months in addition to offering 1.

<Aside type="tip">
  Each offering should ship with: a fixed-scope SOW, a wave plan template, and a hypercare plan. The
  Well-Architected Framework (WAF) assessment + Azure Migrate assessment are pre-requisites that may be sold as a separate, paid
  discovery if the customer is not yet committed.
</Aside>

## Offering 1 – AVS Foundation + first migration wave

**Outcomes**

- AVS landing zone aligned to CAF / Azure Landing Zone (ALZ) Accelerator
- AVS private cloud provisioned (single cluster, AV36 / AV52 / AV64 per sizing)
- HCX deployed with mobility groups + service mesh
- ExpressRoute + Global Reach (where available)
- First wave of 10–50 workloads migrated and validated
- Knowledge Transfer (KT) + hypercare for 30 days post-cutover

**Engagement squad** (typical)

- AVS platform architect (VMware SME — recommend VCP-DCV)
- Azure architect (AZ-305)
- Network engineer (AZ-700)
- Migration lead
- Project manager

**Deliverables**

- High-Level Architecture Document (HLAD) + Detailed Technical Design Document (DTDD)
- Wave plan
- Cutover runbook per wave
- As-built documentation
- Knowledge Transfer (KT) plan + hypercare plan

**Pricing model**

- Default: T&amp;M with capped fee
- Alternative: fixed-fee for landing zone + first wave; T&amp;M for subsequent waves

**Exclusions**

- Long-tail wave execution beyond wave 1
- Application refactor / replatform work
- Long-term operational management (separate managed service offer)

## Offering 2 – DR-to-AVS

**Outcomes**

- AVS DR private cloud provisioned
- SRM or HCX DR configured
- DR run-book + fail-over drill executed
- RPO / RTO targets validated

**Engagement squad**

- AVS platform architect
- Azure architect (network focus)
- DR specialist

**Deliverables**

- DR design document
- DR run-book
- Fail-over drill report
- Hypercare for DR readiness

---

## Offering 3 – Stretched cluster build

**Outcomes**

- AVS stretched cluster deployed across 2 AZs
- Network design for metro latency + bandwidth
- Workload placement strategy
- Cutover of designated mission-critical workload(s)
- DR / failure-mode runbook

**Engagement squad**

- AVS platform architect
- Azure network engineer
- Migration lead (workload-specific)

**Deliverables**

- Stretched cluster design (including SLA math)
- Network design
- Workload cutover plan
- Failure-mode runbook
