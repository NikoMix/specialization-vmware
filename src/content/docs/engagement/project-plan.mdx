## Introduction

This playbook gives a consultant a complete delivery structure for an Azure VMware Solution (AVS) engagement, from the first qualification call through hypercare exit. It is designed to do two jobs at the same time:

1. Deliver a real customer project with clear phases, owners, and outputs.
2. Collect audit evidence as the work happens so the specialization submission is built in, not bolted on.

<Aside type="tip" title="How to use this plan">
  Start this plan during pre-sales and keep it live through handover. Every phase below lists the
  evidence you should capture while the work is happening.
</Aside>

## Phase 0: Pre-sales and Qualification (Week 0–1)

### Activities

1. Run the qualification questionnaire to confirm the customer is a real AVS fit.
2. Validate Azure Consumed Revenue (ACR) eligibility and confirm the attached customer scenario.
3. Confirm DPOR or PAL attachment strategy where relevant.
4. Produce a rough-order pricing estimate using Pricing Calculator assumptions for AVS nodes, ExpressRoute, storage, backup, and monitoring.
5. Draft the statement of work and commercial assumptions.

### Deliverables

- Qualification checklist
- Statement of work (SOW)
- Initial project plan

### Audit evidence collected

- Customer proof letters or production references
- ACR screenshots or partner-center extracts

### Tools

- Partner Center
- Azure Portal
- Qualification questionnaire template
- Pricing Calculator

## Phase 1: Assessment and Discovery (Weeks 1–3)

### Activities

1. Deploy the Azure Migrate appliance and register it to the customer tenant.
2. Connect the appliance to VMware vCenter and validate inventory discovery.
3. Capture dependency mapping and group workloads into migration waves.
4. Generate AVS sizing recommendations in Azure Migrate.
5. Estimate ExpressRoute bandwidth for migration windows.
6. Start the [Azure Architecture Review assessment](https://learn.microsoft.com/en-us/assessments/azure-architecture-review/) with the customer.

### Deliverables

- Assessment report
- Sizing model
- Initial Well-Architected Review findings

### Audit evidence collected

- Assessment screenshots and exports
- Sizing outputs
- Dependency maps

### Tools

- Azure Migrate
- Azure Architecture Review assessment
- RVTools or equivalent discovery tooling if used

## Phase 2: Design and Architecture (Weeks 3–5)

### Activities

1. Align the landing-zone design to Azure Landing Zone guidance and choose hub-spoke or Virtual WAN.
2. Design ExpressRoute, VPN fallback, DNS, and private-endpoint access.
3. Finalise AVS private cloud sizing and node family selection (AV36P, AV52, AV64).
4. Define NSX-T segment layout, gateway model, and distributed-firewall baseline.
5. Design HCX topology for cloud, enterprise, or large-scale migration patterns.
6. Confirm identity and access integration using Entra ID, Active Directory, privileged access, and jump access.
7. Design backup, disaster recovery, Microsoft Defender for Cloud, and Azure Monitor integration.

### Deliverables

- High-Level Architecture Document (HLAD)
- Detailed Technical Design Document (DTDD)

### Audit evidence collected

- Architecture diagrams
- Design document set
- Azure Architecture Review assessment report

### Resources

- [Enterprise-Scale for AVS](https://github.com/Azure/Enterprise-Scale-for-AVS)
- [Azure Architecture Center](https://learn.microsoft.com/azure/architecture/)

## Phase 3: Deploy and Migrate (Weeks 5–12)

### Activities

1. Deploy the Azure Landing Zone using approved Bicep or Terraform modules.
2. Request, review, and approve the AVS private cloud provisioning.
3. Configure ExpressRoute Global Reach and any VPN backup path.
4. Build NSX-T segments, gateways, and DHCP services.
5. Activate HCX and pair the source site to AVS.
6. Execute migration-wave planning, dry runs, and production moves.
7. Run post-migration validation tests per wave.
8. Integrate Azure Monitor, Log Analytics, and alert rules.
9. Enrol guest workloads into Defender for Cloud.

### Deliverables

- Deployment runbook
- Migration wave plan
- Test results
- Monitoring setup

### Audit evidence collected

- Deployment screenshots
- Migration logs
- Monitoring dashboards

## Phase 4: Validate and Handover (Weeks 12–14)

### Activities

1. Complete the Azure Architecture Review assessment and lock the final action plan.
2. Run customer acceptance testing and business sign-off.
3. Finalise the architecture document, design document, and as-built package.
4. Deliver the Knowledge Transfer session schedule and complete the handover workshops.
5. Close the definition-of-done checklist and outstanding issues register.

### Deliverables

- Final architecture document set
- Test results and sign-off pack
- Knowledge Transfer completion record
- Customer sign-off document

### Audit evidence collected

- Full Azure Architecture Review report
- Signed acceptance record
- Knowledge Transfer completion record

## Phase 5: Hypercare Support (Weeks 14–26 / Month 1–6)

### Activities

1. **30-day focus:** watch alerts, tune thresholds, resolve migration defects, and complete restore testing.
2. **60-day focus:** run performance review, validate backup, and review security posture.
3. **90-day focus:** produce capacity-planning and optimisation recommendations.
4. Continue monthly support reporting, backlog review, and ownership transfer.

### Deliverables

- Monthly hypercare reports
- Optimisation backlog

### Audit evidence collected

- Hypercare support records
- Restore-test and disaster-recovery evidence
- Monitoring and operational review reports
