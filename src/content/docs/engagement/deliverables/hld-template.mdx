> Copy this template into your customer-facing High-Level Architecture Document (HLAD). Sections marked **(audit)** map directly to Module B controls.

## 1. Executive summary

- Business drivers
- Forcing function and target dates
- Recommended pattern(s) from the [Reference Architectures](../../reference-architectures/)
- Headline cost envelope

## 2. Scope **(audit – B.2.1, B.3.1)**

- In-scope workloads
- Out-of-scope workloads
- Migration type (P2V / V2V or cloud-to-cloud)

## 3. Azure region and availability-zone strategy

- Primary region
- Disaster-recovery region (if applicable)
- Stretched-cluster zone pair (if applicable)

## 4. AVS private cloud **(audit – B.3.1)**

- Node SKU (AV36P / AV52 / AV64) and count
- Growth plan and expansion trigger
- vSAN Express Storage Architecture configuration
- Customer-managed key decision
- Maintenance-window expectations

## 5. Networking **(audit – B.2.1, B.3.3)**

- ExpressRoute circuits (customer and AVS managed)
- ExpressRoute Global Reach design or rationale if unavailable
- Virtual WAN or hub-spoke routing pattern
- NSX-T design (T0 / T1, segments, distributed firewall baseline, IDS/IPS)
- Public IP pattern (NSX-T DNAT vs Azure-managed public IP)
- DNS and DHCP strategy
- CIDR plan with non-overlap confirmed

## 6. Identity **(audit – B.2.1, B.3.3)**

- Active Directory forest and Entra ID topology
- AVS single sign-on source
- Privileged-access model (PIM, break-glass, jump access)

## 7. Storage **(audit – B.2.1)**

- vSAN capacity, resilience policy, and headroom
- Azure NetApp Files for AVS datastores (if used)
- Blob storage use cases (Content Library, backup target, exports)

## 8. Backup **(audit – B.4.2)**

- Backup tool or partner platform
- Schedule and retention by workload tier
- Restore-test cadence and ownership

## 9. Disaster recovery **(audit – B.2.1, B.4.2)**

- Recovery mechanism (HCX DR, SRM, partner platform)
- Target site or region
- Recovery point objective and recovery time objective targets
- Failover and failback runbook references

## 10. Monitoring **(audit – B.2.1, B.4.2)**

- Azure Monitor for AVS design
- Log Analytics workspace and data sources
- Defender for Cloud coverage
- Sentinel or SIEM integration
- Executive and operations dashboards

## 11. Landing-zone alignment **(audit – B.2.1)**

- Management-group structure
- Subscription topology
- RBAC model
- Policy assignments
- GitOps or AzOps process
- AVS resource-provider registration responsibilities

## 12. Cost model **(audit – A.1.2)**

- Pricing Calculator assumptions
- Reservation strategy
- Connectivity and Azure NetApp Files cost drivers
- Year-1 and year-3 operating envelope

## 13. Risks and mitigations

- Top delivery and operational risks with mitigation owners

## 14. Decision log

- Key design decisions and rationale

## 15. Acceptance criteria

- Customer sign-off criteria for the architecture document
