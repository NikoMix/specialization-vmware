## Why this assessment is mandatory for AVS

The Azure Architecture Review assessment is the most direct Microsoft-authored proof that the AVS design was checked against the Well-Architected Framework (WAF) before handover. It supports:

- **A.2.2** by proving the workload design was reviewed against Microsoft guidance.
- **B.2.2** by showing a formal Well-Architected Review (WAR) output and action log.
- **B.2.1** by feeding design decisions back into the architecture document and design document.
- **B.4.1 / B.4.2** by creating follow-up actions for validation, monitoring, backup, and disaster recovery.

## Step-by-step customer workflow

1. **Schedule the review during design, not after go-live.**
   - Target the end of discovery or the start of design.
   - Confirm the customer workload owner, AVS architect, networking lead, and operations lead will attend.
2. **Open the assessment with the customer.**
   - Use the [Azure Architecture Review assessment](https://learn.microsoft.com/en-us/assessments/azure-architecture-review/).
   - Name the assessment after the customer workload or migration wave.
3. **Select the most relevant pillars.**
   - Minimum for AVS: **Reliability** plus **Cost Optimization** or **Operational Excellence**.
   - Add **Security** when NSX-T, privileged access, or Defender for Cloud decisions are still in flight.
4. **Answer with real deployment assumptions.**
   - Use the chosen AVS node SKU, ExpressRoute topology, NSX-T segmentation plan, backup platform, and disaster-recovery mechanism.
   - Capture decisions on Azure Landing Zone alignment, private endpoints, monitoring workspace, and logging strategy.
5. **Export the report immediately after the session.**
   - Save the PDF in the customer evidence folder.
   - Create an action log with owner, due date, severity, and target milestone.
6. **Replay the findings into delivery artefacts.**
   - Update the architecture document, design document, migration wave plan, test plan, and hypercare plan.
7. **Re-run or review before final handover.**
   - Confirm that critical and high-priority actions are resolved, deferred with customer approval, or tracked in the optimisation backlog.

## Assessment outputs mapped to AVS design decisions

| Assessment output | AVS design decision it should influence | Delivery artefact to update |
|---|---|---|
| Reliability findings | Stretched cluster vs single-zone design, backup RPO/RTO, host-failure handling, disaster-recovery target | Architecture document, design document, service-validation plan |
| Cost Optimization findings | Node SKU sizing, reservation strategy, Azure NetApp Files tier, ExpressRoute bandwidth, HCX wave throttling | Pricing model, project plan, optimisation backlog |
| Operational Excellence findings | Monitoring workspace, runbooks, alert ownership, logging, patching, operational readiness | Hypercare plan, post-deployment documentation, KT plan |
| Security findings | NSX-T distributed firewall baseline, Defender for Cloud coverage, privileged access model, private-endpoint routing | Design document, security backlog, incident runbooks |
| Performance Efficiency findings | Storage policy, vSAN headroom, workload placement, scale-out trigger | Validation plan, capacity plan, monthly operations review |

## Pillar prompts for AVS workshops

### Reliability

- Is a stretched cluster required, or is single-zone AVS acceptable with disaster recovery?
- What is the end-to-end SLA path across AVS, ExpressRoute, Azure NetApp Files, DNS, and identity dependencies?
- How often will restore and failover tests run, and who signs them off?

### Cost Optimization

- Which AVS node family matches the measured workload profile?
- Is the customer buying reserved instances or starting on pay-as-you-go?
- Is ExpressRoute sized for migration peaks as well as steady-state production?

### Operational Excellence

- Which logs land in Log Analytics, and which dashboards are mandatory for day-2 support?
- Who owns alert tuning during hypercare?
- What is the workflow for Microsoft support plus VMware escalation?

### Security

- How is the NSX-T distributed firewall baseline enforced and reviewed?
- Are AVS guest VMs in Defender for Cloud and the correct Defender plans?
- How are privileged access and break-glass identities controlled?

## Recommended meeting outputs

1. Final PDF export from the Azure Architecture Review assessment.
2. Action log with owner, due date, and status.
3. Updated architecture document and design document.
4. Summary slide for the steering committee covering major risks and accepted trade-offs.
