<Aside type="note">
  Run the Azure Architecture Review assessment before go-live. It is the clearest way to prove that
  the workload design was checked against Microsoft guidance and then improved.
</Aside>

## Audit Gate

| Control name | What auditors check | Minimum evidence | Pass threshold |
|---|---|---|---|
| A.2.2 Well-Architected Workloads | Workload designs aligned to Azure Architecture Center guidance and reviewed through the Azure Architecture Review assessment, with findings tracked to closure. | For each of 2 customers: Azure Architecture Review export, reference-architecture alignment note or diagram, and an action log showing how review findings influenced the design. | 2 unique customers; evidence created within the last 12 months; a passed Module A result can be reused for 2 years. |

## Audit-ready evidence pack

1. Azure Architecture Review export with named workload.
2. Architecture-center pattern reference and documented design deltas.
3. Action log or remediation plan tied to the review output.
4. Final customer design readout or sign-off summary.

## Common fail conditions

- Best-practices slide deck submitted instead of the formal Microsoft assessment export.
- No documented connection between the assessment findings and the final design.
- Reference architecture cited verbally but not shown in the evidence pack.
