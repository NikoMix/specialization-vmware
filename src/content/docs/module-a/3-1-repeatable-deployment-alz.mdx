  Pick one infrastructure-as-code toolchain per customer example. The audit wants a clear, repeatable
  deployment path—not a collection of unrelated templates.
</Aside>

## Audit Gate

| Control name | What auditors check | Minimum evidence | Pass threshold |
|---|---|---|---|
| A.3.1 Repeatable Deployment (Azure Landing Zone) | A repeatable Azure Landing Zone deployment aligned to core design areas—identity, networking, resource organisation, policy, and governance—implemented through infrastructure as code. | For each of 2 customers: deployment repository or packaged infrastructure-as-code source, identity configuration evidence, network topology evidence including hybrid connectivity, resource-organisation controls, and Azure Landing Zone Review output. | 2 unique customers; evidence created within the last 12 months; a passed Module A result can be reused for 2 years. |

## Audit-ready evidence pack

1. Repository or release bundle for Bicep, Terraform, or ARM.
2. Deployment guide and pipeline or automation evidence.
3. Identity, policy, RBAC, and naming/tagging controls.
4. Azure Landing Zone Review export with action notes.

## Common fail conditions

- Multiple infrastructure-as-code stacks shown with no standard path.
- Azure Landing Zone Review missing.
- Hybrid network design shown without subscription, policy, or management-group context.
