## What the Auditor Checks

The auditor verifies operational documentation covering **all** of the following for the AVS customer:

- How the partner **documents decisions / architectures / procedures**
- **SOPs for BAU operations** ("how-to" scenarios)
- **AVS host monitoring** solution
- **Azure Monitoring Agent (MMA)** or equivalent on guest VMs
- **Guest-VM logs in Azure Monitor**
- **Azure Update Management + Config Management** (or similar) on AVS guest VMs via Automation Account + Log Analytics
- AVS guest VMs in **Defender for Cloud** (Defender for Servers)
- **Backup** via Azure Backup Server (or licensed equivalent) **with restore demonstrated**
- **DR via HCX / SRM / partner solution**
- **Automated DR** with workloads deployable to alternate site in running state

**Typical questions:**
- Show your AVS SOPs / "how-to" library.
- Where are the AVS host monitoring dashboards?
- Show the AVS guest VMs in Defender for Cloud.
- Show a restore demonstration (test or real).
- Walk us through the automated DR fail-over.

## Evidence Guidance

### Documentation process

A 1-page description of how your team manages docs:
- Repository (Confluence / SharePoint / Git wiki)
- Review cadence
- Ownership
- Versioning standard

### AVS BAU SOPs

Minimum SOP coverage:
- Add / remove AVS host
- Patch ESXi (Microsoft-managed for AVS — document the customer-facing process for change windows)
- Backup operations
- Restore operations
- DR fail-over + fail-back
- Incident triage path (joint Microsoft + VMware support case)

### Monitoring stack

Layered approach:
| Layer | Tool |
|---|---|
| AVS host metrics (vSAN, ESXi, NSX-T) | Azure Monitor for AVS |
| Guest OS metrics + logs | MMA / Azure Monitor Agent → Log Analytics |
| Application logs | Application-specific (often into the same workspace) |
| Security signal | Defender for Cloud + Sentinel |

### Update + Config Management

- Automation Account + Log Analytics for Update Management
- DSC / Guest Configuration for Config Management
- Schedule and reporting evidence

### Backup + restore

- Azure Backup Server VM image backup (or partner equivalent like Veeam, Commvault)
- Backup schedule + retention
- **Restore demonstration**: at least one successful restore screenshot or video

### DR

- HCX DR or SRM topology diagram
- Automated DR run-book reference (also in [`engagement/deliverables/runbook-template`](../../engagement/deliverables/runbook-template/))
- Fail-over evidence: VMs powered on at the alternate site

## Common Gaps

- **Restore not demonstrated**: Most common miss. Schedule a test restore during hypercare.
- **Automated DR is only designed, not exercised**: Run a tabletop or partial fail-over and capture evidence.
- **MMA / Azure Monitor Agent gap on AVS guests**: Common — guest OS agent rollout lags VM migration.
- **SOPs incomplete**: The SOP library must cover BAU end-to-end, not just provisioning.
